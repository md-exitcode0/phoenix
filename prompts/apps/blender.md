Blender interface workflow

Use the active desktop backend's input and images. When the user requires UI-only work, do not substitute Python, the console, bpy, an API, or a prebuilt asset. Use F3 for named operators and individual key actions for sequential shortcuts; `r y 20` is a sequence, not one key combination. Use `num1`/`num7` or their supported keypad equivalents for orthographic views. Focus the viewport before modeling shortcuts.

Choose a modeling approach that matches the shape. A curved, tapered solid usually benefits from connected cross-sections: start from a small ring, extrude sections along the curve, vary their size and orientation, close the ends, then smooth/subdivide. Overlapping spheres or metaballs can become lumpy and are hard to refine at tips. Keep thin stems and caps attached deliberately. Evaluate the silhouette in at least two views before spending time on materials. Smooth shading alone does not remove a visibly polygonal outline.

Interpret each view before criticizing the geometry. Read Blender's view label and axis gizmo; a curve can look straight from an orthogonal direction, and foreshortening can make a long stem look short. Compare the reference and render from comparable directions, and use a second view to resolve an apparent defect before editing. Do not require every projection to reproduce the same curved silhouette. Solid viewport shading establishes shape, not the final material or lighting. Keep a verified improvement unless the combined views show a real remaining defect.

For a continuous organic object, inspect the junctions as geometry rather than treating overlap as attachment. Joining object names or smoothing normals does not weld separate surfaces. Prefer a continuous surface through the body and neck, or bridge compatible open edge loops and check the transition from two angles. Avoid internal end caps intersecting a neighboring surface. A seam that remains after repeated smoothing or scaling calls for changing the construction, not hiding it under another sphere or color band. Preserve an editable backup before structural changes.

Judge materials under neutral light before adding a presentation look. Compare broad color, roughness and the scale of variation with the real reference. Subtle pigment is not a layer of raised objects; excessive bump or high-contrast noise can make skin resemble cut flesh. Blender shades in scene-linear color, and color-picker modes vary by version: confirm whether a value is linear or perceptual before copying display RGB into a shader. Changing exposure to fix the base material can conceal rather than fix the color error. After each significant change, inspect a whole view and a useful detail; after the final file changes, reopen that saved version in Blender so the inspected app matches the delivered artifact.

Keep stages visible: establish geometry, refine shape, assign materials, compose a preview, and deliver files. Batch familiar transforms within a stable mode. Stop at an unfamiliar dialog or a changed mode and inspect its actual state. Confirm a newly added object exists before continuing many transforms. Avoid correcting an object whose identity or mode you have not checked.

Before editing transforms, confirm the selected object's name in the viewport or Properties header. Clicking an Outliner row is not proof of selection. When editing numeric fields, change one value first and check that the displayed value actually changed before batching the rest. A successful input receipt only means input was sent. If a value or selection stays unchanged after two attempts, stop repeating that coordinate sequence: inspect the current target, then use a different visible control or a viewport keyboard transform on the verified selected object. Do not spend repeated batches changing coordinates slightly while the same state persists.

Saving is a separate acceptance step. Blender's Save As dialog has different directory and filename fields. Put the containing folder in the location field and only a basename such as banana.blend in the filename field. Full paths typed into the filename field can have slashes replaced with underscores and land in the home folder. Check the location and basename before confirming. A title bar showing the name alone does not prove the requested directory. Reopening File > Save As can reveal the currently saved location; cancel after inspecting if no change is needed.

When changing from the directory field to the filename field, the first click can dismiss the previous edit without activating the new field. If typing does not visibly change the filename, stop typing: click the filename field, wait about 300 ms, then click it again and wait before Ctrl+A and typing. Use two separated single clicks, not an immediate double-click. Press Enter and inspect the committed basename. The Save button can similarly need a first click to leave text editing; if the same dialog remains open after that click, verify the directory and filename again, then confirm Save once more. Stop after this bounded recovery if it still fails. Verify the actual file at the requested path; do not repeat typing and Save batches while the filename stays Untitled.

For a clean preview, first disable viewport overlays so the grid, axes, 3D cursor and selection outlines are absent. In Blender’s default keymap, Shift+Alt+Z toggles overlays in the targeted 3D viewport. It is a toggle: inspect the current state and resulting pixels, rather than pressing it repeatedly. Frame the complete object with some margin. Focus the 3D viewport and use F3 "Viewport Render" (the operator's exact name), or View > Viewport Render Image. Then use the Image editor's Save As. A camera render is another option. "Save Screenshot" saves interface chrome and is not a substitute for a clean preview. Menu captions can differ from F3 operator names; if search misses, inspect the actual menu rather than repeating the phrase. Check the exported image at the exact requested path and look for cropping, loose parts, faceted tips, unassigned materials and unwanted interface elements. A viewport render can still contain overlays; the absence of editor panels alone does not prove a clean image. If the result is not acceptable, repair that defect before marking the relevant task complete.

Keep successful work when fixing delivery. Do not rebuild geometry merely because the save dialog was used incorrectly. Report incomplete output truthfully; a successful input receipt or a completed checklist is not proof that the file or design meets the brief.

When scripting is allowed, put failure handling before the script: `blender --background --python-exit-code 1 --python create_scene.py`. Blender processes arguments in order; placing `--python-exit-code` after `--python` can report exit 0 even when that script raised an exception. Inspect the command output for Python errors and confirm the expected render was updated before reviewing it. A previous image left on disk does not validate a new scene edit.

Reference: Blender manual, Bridge Edge Loops (https://docs.blender.org/manual/en/5.1/modeling/meshes/editing/edge/bridge_edge_loops.html) and Color Management (https://docs.blender.org/manual/en/4.5/render/color_management.html). Match controls to the installed version.


When a real reference or earlier render is available, inspect the current render with `image_analyze` and `reference_paths` (up to two whole images) on a native-vision acting model. The primary image and references then reach the same request in a known order. Use this for actual shape/material comparisons instead of remembering a reference seen many edits ago. A primary crop does not crop its references; also compare a whole-object view before accepting the result. The comparison identifies visible differences; it is not a pass certificate.
